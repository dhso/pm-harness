# 整理项目知识

先搜索索引，再只打开相关的 Wiki、项目、来源和证据记录。写入前查询 `wiki.register` 紧凑契约；回答应以项目文件为依据，有帮助时引用路径和来源 ID。

区分已确认事实、解释、假设和未解决冲突。若缺少必要信息，明确说明，并指出最小且有用的下一份来源或问题。

整合知识时：

- 合并重复主题页面，不要反复复制同一事实；
- 保留来源和最近复查日期；
- 使用稳定 ID 关联需求、决定、任务、风险和交付物；
- 将过时主张移入已替代部分，不要静默删除历史；
- 不把原始沟通材料放入 Wiki。

通过 `wiki.register` 登记和更新页面，不直接编辑 `knowledge/catalog.json` 或生成的索引。每个页面包含稳定的 `WIKI-###`、来源、关联 ID、评审状态和复查日期；内容更新会刷新最近复查时间。不要留下未登记的 Markdown 孤立页面。

知识已应用后，用 `inbox.transition` 将对应条目转为 `applied`，并在 `applied_to_ids` 记录 Wiki 或结构化事实 ID；需要用户判断的条目转为 `needs_confirmation` 并保留原因。不要让 `triaged` 条目停在“已分流、未执行”状态。

只有信息适合跨会话长期保留时，才重建知识索引并更新记忆。

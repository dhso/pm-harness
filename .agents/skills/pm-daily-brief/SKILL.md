# 梳理今日工作

运行 `node .harness/scripts/harness.mjs brief --json`，需要上下文时再检查其中引用的记录。

默认用三个小标题加项目列表，上下排列；需要比较同类信息或用户指定时再用表格。每项简述原因和下一步，空组省略：

- **风险与紧急事项**（`attention_actions`，概览见 `attention_summary`）：阻塞或逾期的任务和里程碑、今日到期的工作、需要响应或复查的风险、已到期未交付的成果，不设上限，每项都要覆盖。同类事项较多、逐条列出会淹没重点时，先用 `attention_summary.by_kind` 给数量和共同影响，再列最需要决定的几项，其余按类别并列，不截断、不省略。
- **常规推进**（`top_actions`）：承诺、依赖、近期里程碑和到期任务等日常行动，最多三项。
- **未解决问题**（`issue_actions`）：状态为 open 或 monitoring 的问题，不设上限，不占常规额度。数量多时按负责人或主题归并，不猜测严重度；已缓解或已接受的问题不在此列，需要时用 `query` 查看。

同一事项不跨栏重复。按需补充近期里程碑、交付、待决定或干系人跟进、尚未分流的来源、近期成果及到期的知识或规则复查，避免复制完整清单。其他开放风险保留在风险摘要中，不因未进入行动栏就声称没有风险。

三组为空时可说明“根据当前记录，未发现需要优先关注的事项”；不据此断言项目没有风险或所有工作已经完成。

若优先级冲突，提出一个聚焦的取舍问题。同一天内除非状态发生实质变化，否则不要在每次对话重复简报。

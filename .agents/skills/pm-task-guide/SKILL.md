# 梳理项目任务

读取项目概述、当前状态、当前记忆，以及与请求相关的索引。

简单事实问题直接回答。其他请求先确定主要结果属于研究、来源摄取、需求、计划、状态、沟通、交付物、评审或复盘中的哪一类，再选择范围最窄的专用 Skill。

## 组合路由

- 选择一个 `kind: workflow` 的主 Skill 负责结果和项目写入。
- 只有产出确实需要时才加载 `kind: capability`；能力 Skill 不改变主流程的审批边界。
- 多个工作流必须串联时明确主次和交接结果；关键路径仍不明确时只问一个会改变路径的问题。

对于重要工作，建立精简的任务契约：

- 期望结果及其重要性；
- 目标受众或决策人；
- 所需产出及格式；
- 截止日期或决策日期；
- 来源材料和约束；
- 可观察的验收标准。

只询问会实质改变结果的缺失信息；说明低风险假设，不让用户重复项目文件中已有的事实。由主 Skill 完成项目收尾；没有长期结果的问题不写活动记录。

# 项目邮件写作

一封邮件确定一个主要目的；目的冲突时拆分或明确主次。

```text
主题 = 项目/事项 + 结论或期望动作 + 必要期限
正文 = 结论/变化/请求 → 必要事实与影响 → 负责人/动作/日期 → 回复事项与期限
```

短邮件不强加章节；多组信息、多名负责人或多条时间点再用列表或表格。需要内容脚手架时用 `templates/project-email.md`。

| 场景 | 补充必要信息 |
|---|---|
| 决策请求 | 决定对象、为何现在决定、选项、建议、影响、最晚决定时间 |
| 风险升级 | 阻塞、已发生/预计影响、已尝试动作、需要谁提供什么支持、最晚响应时间 |
| 会议跟进 | 已确认决定、行动、负责人、期限、待确认项；讨论不自动成为决定 |
| 交付 | 成果名称/版本、位置或附件、适用范围、已做检查、限制及确认要求；生成不代表发送或验收 |

未知负责人标待分配；缺失的称呼或署名可省略或列待确认，不虚构姓名、职位、公司或历史沟通。将收件人、抄送、署名、附件和链接一并纳入[共用复核](plain-language.md#有限复核)；仅将影响发送的未决项列为待确认。

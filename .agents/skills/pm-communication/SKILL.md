# 编写项目邮件与汇报

```text
相关状态/来源 + 已确认沟通偏好 → 明确受众、目的、期望动作/决定、期限、渠道和语气
→ 按对应参考成稿 → 复核保真与表达 → 输出一个推荐版本
```

只补查影响正文的记录或缺口；澄清和低风险假设按 `AGENTS.md`。已读偏好可复用，需要补查时用 `query preference --where scope=communication`。

| 条件 | 读取 |
|---|---|
| 起草或改写沟通文本 | [说人话与保真](references/plain-language.md) |
| 邮件、跟进、提醒、升级或决策请求 | [邮件写作](references/email.md) |
| 周报、阶段报告、管理层简报或专项报告 | [汇报写作](references/report.md) |

正文涉及受控事项时核对批准，否则写为提议；不替收件人作决定。实际发送须有用户明确授权及对应工具能力，草稿不代表已批准或已发送。

被其他工作流作为写作子任务调用时，只返回成稿和关键缺口，由调用方统一写入与收尾，不再回调调用方。以下交接与写入仅用于本流程直接承接的任务：

- 用户确认已发送 → 记录精简活动；重要证据再登记来源定位、时间和关联对象。
- 直接承接正式文件任务 → 将文稿、受众、格式与检查结果交给 `pm-deliverable` 继续文件和生命周期处理；普通聊天草稿直接返回，无需建档。
- 偏好与项目事实收尾 → 按 `AGENTS.md`。

默认只交付成稿，不展示写作过程或多套版本。关键缺口在成稿后简列“发送前待确认”；没有则省略。

# 创建和管理交付物

读取 `.harness/references/deliverable-policy.md`、项目上下文、相关来源和验收标准。

开始重要创建工作前，确认目的、受众、使用场景、格式、截止时间、必需信息或数据以及评审标准。使用 `templates/` 中最接近的模板作为内容脚手架，并按实际需要调整。

正式报告使用 `pm-communication` 保持事实准确并使叙述简洁自然；本 Skill 继续负责文件、版本、评审和交付生命周期。

在初稿之前或同时登记交付物。工作文件放在 `deliverables/current/`；使用清晰稳定的文件名并递增版本。绝不覆盖已批准的终稿。

涉及 DOCX、XLSX 或 PPTX 时，读取并遵循 [officecli](../officecli/SKILL.md)，由它负责文件级读取、编辑、批量操作和格式校验；视觉质量重要时生成临时预览，渲染产物不得进入 Git。本 Skill 继续负责交付物目的、版本、审批、交付和验收生命周期。

交付物面向外部受众时，遵循 `AGENTS.md` 的“对外表达”准则，并检查正文、页面、图表和附件不包含内部 ID、文件路径或晦涩的 Harness 术语。

通过类型化记录操作准确更新状态：创建不等于交付，交付不等于验收。批准和验收需要具有匹配结构化权限范围的有效干系人，以及用户确认业务事件确已发生。修改已批准内容需要已批准的变更请求和新的版本/替代链。

收尾时报告文件路径、已执行的检查、当前生命周期状态、剩余评审行动和索引更新。

# 规划项目工作

读取 `.harness/references/schedule-policy.md` 以及项目目标、需求、风险、决定和交付物。

建立以结果为导向的计划，包含稳定 ID、明确负责人、依赖关系、验收/证据和明确的下一步行动。避免创建无法验证的任务。

只有用户批准计划后才能设置基线日期；日常进度只更新预测和实际。修改已批准基线时按 `schedule-policy.md` 创建精确变更请求，并在应用前说明下游影响。

按 `schedule-policy.md` 选择类型化操作：同一逻辑变更涉及多项时使用批量契约并一次预演、一次提交；状态转换提供实际发生时间。提交后重建甘特图，并记录重要决定和未解决依赖。

总结关键路径、近期里程碑、主要风险和待决定事项，不要复述完整任务清单。

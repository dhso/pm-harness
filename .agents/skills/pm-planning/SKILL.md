# 规划项目工作

读取 `.harness/references/schedule-policy.md` 以及项目目标、需求、风险、决定和交付物。

建立以结果为导向的计划，包含稳定 ID、明确负责人、依赖关系、验收/证据和明确的下一步行动。避免创建无法验证的任务。

只有用户批准计划后才能设置基线日期。日常进度只修改预测和实际字段，不修改基线。如果请求的工作要在已批准基线上新增、修改或删除内容，为每个目标创建包含精确结构化前后值的变更请求，并在应用前说明下游影响。

通过类型化记录操作应用计划变更。一次逻辑变更涉及多个任务或里程碑时，先查 `schedule.batch-upsert` 契约并一次预演、一次提交，不要循环调用 `schedule.upsert`；单条字段更新使用 `schedule.upsert`，状态转换使用 `schedule.transition` 并提供实际发生时间。初始基线先整体写成草稿，再调用一次 `schedule.baseline.approve`。确保基线修订、摘要、审批和变更日志保持一致。执行重建，使 `project/gantt.md` 反映规范数据。记录重要的计划决定和未解决依赖。

总结关键路径、近期里程碑、主要风险和待决定事项，不要复述完整任务清单。

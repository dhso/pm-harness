# 文件边界与外部版本控制

Harness 的运行、校验和撤销均不依赖 Git。项目经理无需安装、配置或理解 Git；Harness 不执行初始化、提交、分支、远端、历史改写或清理操作，也不会因为目录是否为仓库而改变行为。

## 长期事实

Harness 指令、实体 `.agents/skills/`、可执行契约、项目事实、需求/计划/风险/决策、结构化来源与证据、精选 Wiki、当前和批准交付物、结构化索引、活动事实与生成视图、记忆和项目规则。

## 本地或临时内容

原始邮件/聊天/截图/附件、历史草稿和旧二进制、渲染文件、缓存、备份、临时文件、完整聊天或工具日志、凭证和秘密。原始资料被排除是为了控制仓库体积与噪声，不要求对正常项目内容做脱敏。

归档原件放在 `archive/files/`，结构化索引保存在 `archive/index.json`。每条索引使用稳定 `ARC-###`，并至少保存所归档对象的逻辑 ID、文件名、类型、SHA-256、归档时间、原因、替代对象和可用状态。凭证、Token、Cookie、验证码、私钥和 `.env` 不得写入项目资料。

## 撤销

每次新操作在追加型操作日志中保存受影响记录的恢复前内容、写入后哈希和必要的 store metadata。`undo <operation_id>` 在写锁内追加一条 `operation.compensate`，恢复结构化事实并保留原操作。实际执行必须携带用户确认时间；它不会删除审计记录，也不会删除归档原件。

以下情况拒绝补偿：目标不是最近的有效操作；操作包含受控或已批准变更；旧记录没有补偿快照；目标内容已发生后续变化；操作写入了需要人工判断的文档内容。更早或不可补偿的事实使用正向修正，受控事实走新的变更请求。

补偿删除新建实体后，其稳定 ID 仍由操作历史保留，不会重新分配。复合工作流作为一个整体补偿，不能把补偿步骤嵌入工作流。

## 外部工具

开发者或组织可以按自己的政策使用 Git、备份或同步工具；这些都在 Harness 之外。仓库附带的 `.gitignore` 和 `.gitattributes` 仅为选择使用 Git 的维护者提供安全默认值，不构成运行依赖。

Markdown、JSON 和 MJS 统一使用 LF。模板不得追踪软链接；下载压缩包或复制到 Windows 后必须仍能发现全部 Skills。
